## 1. 目标与范围

用户希望项目实际使用 LangChain（大模型应用框架）、LangGraph（流程编排框架）和 LangSmith（执行追踪平台），并能理解各框架在项目中的职责。采用已确认的渐进迁移方案，继续使用通义千问和现有业务接口。

迁移完成后：

- LangChain 实际负责聊天模型调用、标准消息、工具绑定与工具调用接口，而不是仅增加依赖。
- LangGraph 继续负责 agent（模型决策）与 tools（工具执行）两个节点之间的有限循环。
- LangSmith 在显式开启且配置有效时追踪请求、图、模型、检索和工具的关联关系；默认关闭上传，不要求开发者先拥有追踪密钥才能聊天。
- 普通调用与流式调用均支持连续工具决策，修复当前流式路径关闭工具的问题。
- 保留会话隔离、技能权限、真实 MCP（模型上下文协议）通信和暂停恢复。

本次不迁移数据库、不重建向量索引、不更换嵌入模型、不引入高层预制 Agent、不增加新工具、不部署外部服务，也不更改前端产品流程。

## 3. 框架职责与数据流

```text
现有接口与会话服务
  → 建立请求追踪上下文，加载历史并转为标准消息
  → LangGraph 状态图
      → agent：过滤工具权限 → LangChain 绑定工具 → 调用或流式调用模型
      → 有完整工具调用：tools → 安全执行层 → LangChain 工具适配器
          → 本地计算器 / 现有知识检索
          → MCP 客户端 → 独立 workspace 服务
      → ToolMessage（工具结果消息）回到 agent
      → 完成、零命中、步数耗尽或控制信号终止
  → 统一结果整理与政策摘要校验
  → 保存用户可见回复并返回现有响应

显式开启追踪时：上述执行关联到 LangSmith，上传内容受脱敏策略限制。
```

保留自定义工具节点，避免预制执行器绕过当前业务安全入口。LangChain 工具适配器只能在权限检查后调用；不能因为模型已绑定工具就跳过执行时校验。

## 4. 模型与消息迁移

### 4.1 模型适配

通过 `langchain-openai` 的 ChatOpenAI（聊天模型适配类）连接当前 `QWEN_BASE_URL` 的标准聊天兼容接口，保留 `DASHSCOPE_API_KEY`、`QWEN_MODEL` 和超时配置。显式使用聊天补全接口，不切换到其他接口协议。

当前流程不需要推理内容字段，继续关闭思考输出；供应商参数通过独立扩展参数传递。ChatOpenAI 官方说明只保证标准 OpenAI 接口字段，不保证第三方扩展，因此兼容性必须通过受控 HTTP（网络请求）响应测试，覆盖工具绑定、流式工具分片、普通文本、用量缺失和错误转换。不得把安装成功当作兼容验证。

不保留第二套直接 SDK 模型调用作为正常业务分支。底层 SDK 可继续作为适配包依赖以及异常类型来源。

### 4.2 标准消息

运行态使用 HumanMessage（用户消息）、SystemMessage（系统消息）、AIMessage（助手消息）和 ToolMessage（工具结果消息）。模型工具调用使用标准的 name、args 与 id 字段。

在单独的消息转换模块处理以下边界，节点内部不散布格式判断：

- 数据库中的 role/content 历史转为标准消息。
- 旧检查点中的 OpenAI 工具调用结构转为标准消息。
- 新检查点写入带版本的标准消息表示，保留可恢复的工具调用标识。
- 公共结果只提取回答文本，不把消息对象、工具参数或模型元数据返回前端。

旧检查点须能够继续读取；未知版本安全报错，不猜测恢复格式。不修改已有数据库表结构。

## 5. 工具与任务技能

### 5.1 工具适配

用 LangChain 的结构化工具接口包装已注册工具。业务函数、工具描述和参数模型保留单一来源，适配器从注册表构建，不复制计算器或检索实现。

- 本地工具继续使用 Pydantic（数据校验库）模型拒绝非法参数。
- MCP 工具继续使用发现得到的 JSON Schema（JSON 参数结构规范），不能转换时默默放宽校验。
- 适配器只接收模型可提供的参数；knowledge_base_id（知识库标识）由可信后端上下文注入。
- 工具权限取当前请求允许列表与任务技能允许列表的交集，在模型可见列表和实际执行入口各检查一次。
- MCP 保留宿主允许列表和真实客户端调用，不能直接导入服务端函数。

统一执行入口同时服务图节点与原有直接调用方，错误通过已有安全提示返回，不暴露参数、文档或内部异常。

### 5.2 路由与任务技能

保留“已选择知识库时默认检索”的规则与例外顺序。首次执行之后由模型根据结果继续选择工具，不因存在流式回调而关闭工具。

未选择知识库时，计算、时间和文本统计也能调用工具；明确的专用工具意图不依赖知识库标识才能生效。普通寒暄可以直接回答。

政策摘要仍由现有激活规则选择，并且只能使用检索工具。将最终回答整理为公共函数，同步入口和可恢复入口都执行同一套非空校验与原文依据校验。流式任务的最终完成事件和数据库回复以校验后答案为准；政策摘要在校验完成前不发送未经校验的正文片段。

## 6. 循环、流式输出与控制行为

### 6.1 五步限制

继续使用 MAX_STEPS=5，模型节点与工具节点各计一步；每个工具节点只执行一个工具。典型上限是三轮模型、两次工具执行。第五轮若模型仍要求工具，返回固定的步数耗尽提示，不执行额外工具。

不为流式分类额外发起未计数的模型请求。调用次数与耗时包括因暂停而中断的真实调用，恢复时累计；模型内部 SDK 重试不作为额外图节点。

### 6.2 流式工具调用

使用 LangChain 流式消息块累计工具调用，直到名称、标识和参数完整并通过校验才进入工具节点。工具参数分片和推理内容不得通过正文回调显示。

能确定为纯最终文本的阶段按片段发送。允许工具的决策阶段如不能提前确定文本是最终回答，则缓冲文本，完成消息分类后发送；不能以提前输出为理由把混合工具决策内容当作最终答案。政策摘要额外遵守第 5.2 节的校验要求。该策略可能增加部分回答的首字延迟，但无需增加模型调用，也保留连续工具能力。

工具结果继续作为不可信数据返回模型，并包含对应工具调用标识。一次响应中出现多个调用时安全拒绝，不执行其中一部分。畸形参数转换为可识别的工具错误，不能将其视为正常回答或成功计算。

### 6.3 暂停、恢复、停止和超时

- 模型流的每个分片之间检查控制信号，检测后关闭上游流。
- 流式工具参数尚未完成时暂停：不执行工具、不保存半成品调用；恢复时重新完成该模型决策。
- 完整模型工具调用已经持久化时暂停：恢复进入工具节点，不重复请求已完成的模型决策。
- 工具执行中不承诺强制中断；在工具返回后的节点边界响应控制，保留现有 MCP 超时。
- 已执行工具不因消息格式迁移而再次执行；回答前缀不重复发给前端或重复写入消息列表。
- 检查点不保存回调、密钥和完整工具结果。由于工具结果会被省略，恢复后如需要该数据，应重新取得所需检索依据；不得把“结果已省略”的占位文字当作事实回答。
- 全局五步预算在暂停恢复之间累计，不因恢复清零；缺少依据且预算不足时明确安全结束。

继续使用现有 SQLite（轻量数据库）检查点，不引入 LangGraph 持久化后端。

## 7. LangSmith 追踪与隐私

### 7.1 配置与关联

新增明确配置说明：`LANGSMITH_TRACING` 默认 false、`LANGSMITH_API_KEY`、`LANGSMITH_PROJECT` 与可选 `LANGSMITH_ENDPOINT`。只在显式开启并具有有效必要配置时创建追踪客户端，缺少配置时安全降级。

请求级上下文覆盖图、模型和工具。普通请求关联已有 request_id（请求标识）；可恢复任务关联已有 run_id（任务标识）。恢复操作建立新的执行片段，通过相同任务关联标识连接，不复用已结束的追踪运行标识。

后台工作线程必须显式携带追踪上下文，不依赖请求线程的隐式变量。传入图、模型和工具的 RunnableConfig（执行配置）传播回调和关联信息。

### 7.2 上传边界

本次只提供元数据追踪模式：

- 允许上传：随机请求关联标识、节点与工具名称、模型名称、技能名、步骤、状态、耗时、命中数量、供应商实际返回的用量计数。
- 不上传：用户问题、会话历史、回答正文、系统提示词、工具参数与结果、文档片段、知识库标识、用户身份、Cookie（会话凭据）、原始 IP（网络地址）、接口密钥和异常原文。
- 图状态、模型与工具的自动追踪都必须应用输入输出隐藏；元数据和错误通道同样需要允许列表处理，不能只隐藏 messages 字段。
- 测试检查最终提交给追踪客户端的完整载荷，不仅检查配置值。
- 追踪网络异常不得改变聊天结果或回滚已成功的业务执行；不得吞掉真实模型或工具异常。日志只输出安全诊断类型。

默认关闭时，即使依赖已安装，也不得创建外部追踪请求。MCP 子进程环境允许列表不增加 LangSmith 或模型密钥。

LangSmith 平台真实上传验证需要可用账号、密钥与网络；本地测试使用内存记录器或模拟传输，不发送真实用户数据。不把本地模拟通过描述成平台已验证。
