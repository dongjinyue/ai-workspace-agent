# AI Workspace Agent 公共访客与管理员模式规格

## 目标与已确认体验

让 `agent.dongjinyue.cn` 无需访客输入共享访问令牌即可试用；唯一管理员通过个人网站使用的 Supabase（身份认证服务）账号登录并保持无限额度；所有其他访问者按访客规则使用，保护管理员对话和模型 API（接口）费用。

- 域名打开后直接进入访客工作区，不显示部署者共享访问令牌页。
- 管理员可从登录入口使用个人网站现有 Supabase 邮箱和密码登录；不提供注册。后端只把 Supabase 返回并验证过的用户 ID 与配置的 `ADMIN_USER_ID` 精确比对，匹配才赋予管理员角色。
- 未匹配管理员的访问均视为访客；不接受浏览器提供的角色或用户 ID 作为授权依据。
- 每个访客会话每天最多提交 10 条顶层问题，以 `Asia/Shanghai`（中国标准时间）自然日重置。每次提交计 1 次，不按 Agent 内部模型/工具步骤重复计数；成功或失败的已接收请求都消耗额度。
- 另加 IP（网络地址）保护：每个来源 IP 每分钟最多 5 次 AI 请求、每天最多 30 次 AI 请求。IP 不是身份，访客会话和 IP 两种额度需同时满足。
- 页面显示访客剩余额度和下次重置时间；超限时不调用模型，并说明何时可再次使用。管理员无访客额度限制，但仍受基础服务稳定性限流。
- 访客可创建、读取、重命名、删除自己的对话，并可查询只读知识库、使用经过审核的只读工具；不得读取或操作其他访客及管理员对话。
- 访客不能上传文档、修改/删除共享知识库或执行未审核的 MCP（模型上下文协议）操作。管理员保留现有全部功能。

## 身份、请求和数据流

### 管理员登录

1. 前端使用 Supabase 官方 JS（JavaScript）客户端对现有项目执行邮箱/密码登录；浏览器只持有公开 publishable key（公开密钥），不接触 service role（服务角色密钥）。客户端会话仅保存在当前标签页的 `sessionStorage`，避免把管理员会话长期留在共享设备上。
2. 前端为 API 请求附上 Supabase access token（访问令牌）。
3. FastAPI 服务端向 Supabase Auth 用户验证端点核验令牌，并将其返回的稳定用户 ID 与服务器环境变量 `ADMIN_USER_ID` 精确比较；不信任未经验证 JWT、`user_metadata`、浏览器角色字段或自报用户名。
4. 管理员每个受保护请求均在服务端重新获得角色。身份服务不可用或令牌无效时按拒绝处理；前端退出会清理本地会话。

### 访客身份

- 后端首次请求签发密码学安全随机访客会话 Cookie，设置 `HttpOnly`、`Secure`、`SameSite=Lax`、有限有效期；关键请求检查同源来源并启用 CSRF（跨站请求伪造）防护。
- Cookie 中不含管理员权限。后端只保存访客随机 ID 的 HMAC（带密钥的哈希）摘要，不能由数据库记录反推出原 Cookie。
- 用 Nginx 传入的 `X-Real-IP` 识别真实访客 IP；仅在请求确实来自本机可信反向代理时信任该头。不要采用任意客户端传入的 `X-Forwarded-For` / `X-Real-IP`，否则可伪造额度。
- 对 IP 只存带独立服务器密钥的 HMAC 摘要和额度计数，不在额度表保存原始 IP；日志不得写完整令牌、提示词或原始地址。保留期限限于防滥用所需窗口。

### 会话所有权与权限

- 在 SQLite（轻量关系型数据库）新增会话所有者字段和访客额度记录；所有现有会话迁移为唯一管理员所有。对话 ID（标识符）只是定位符，不是权限。
- 所有会话的创建、列表、读取消息、重命名、删除及 Agent 聊天入口都必须在服务端以当前管理员或访客身份限制所有者。陌生访客伪造管理员/其他访客 ID 时一律不可见，返回与不存在相同的结果。
- 新会话和首条聊天并发时必须归属当前身份；任何兼容接口（包括旧 `/api/chat`）也经过相同授权和额度策略，避免绕过主聊天入口。
- 管理员能继续访问迁移前全部数据；访客不能浏览旧管理员历史。
- 访客只能读取明确配置为公开的知识库；服务器 `PUBLIC_KNOWLEDGE_BASE_IDS` 默认空列表，既有知识库默认保持管理员私有，不能因为开放访客入口而自动公开。访客工具允许列表限于无副作用的本地计算/公开知识检索和已核准 MCP 工具；文件上传、知识库变更端点对访客返回拒绝。

## 额度、费用和可靠性

- 使用持久化 SQLite 记录访客每日计数和 IP 级每分钟/每日计数，通过事务或原子条件更新保证并发请求不能多扣或超额通过；应用重启后计数不清零。
- 额度键按上海时区日期计算；数据库保存 HMAC 身份摘要、日期、计数和必要时间戳，限制清理策略避免无限增长。
- 只有顶层 AI 生成请求消耗 10 次访客日额度与 IP AI 请求额度；用于恢复对话、列会话、读取知识库的普通请求不消耗 AI 额度，但继续受基础 API 频率限制。
- 额度通过后即扣，避免重复失败免费消耗；超限请求不得进入 LLM（大语言模型）或工具执行链。
- 保留 Agent 现有最多 5 步限制、请求长度限制和输出限制；IP 级每分钟限制和每日上限应独立于当前进程内泛化 API 限流。
- 个人额度并非全站费用硬上限：供应商的预算告警/封顶能力应在发布前核实；不将“每天 10 次/访客”宣称为绝对防刷或成本保证。
- 单实例 SQLite 与本地限流适用于当前单容器部署；扩展多实例前迁移至共享持久化限流存储。

## 配置与部署

- 后端必须配置 Supabase 项目 URL、公开 API key（仅用于 Auth 验证）和唯一 `ADMIN_USER_ID`；额度 HMAC 使用独立高熵服务器密钥。缺少管理员配置时不能把任何用户视为管理员。
- 前端使用 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISHABLE_KEY`；二者为公开配置，不包括模型/服务端机密。
- 前端依赖锁定版本的 `@supabase/supabase-js`；仅用于 Supabase Auth 登录、续期与退出。后端必须核验 Auth 用户，不得因浏览器拿到 access token 就默认其为管理员。
- 后端通过 Supabase Auth 的用户校验接口核验 Bearer access token，并只在 Auth 返回的用户 ID 等于 `ADMIN_USER_ID` 时认定管理员；仅使用 publishable key 调用身份验证，不添加服务角色密钥。Auth 暂时不可用时管理员接口拒绝请求，访客只可使用访客权限。
- 后端 `PUBLIC_KNOWLEDGE_BASE_IDS` 显式列出可由游客检索的知识库 ID，未列出的现存知识库一律不可被游客查询；默认不公开任何现有私人文档。
- 后端模型供应商密钥仍仅保存在服务器后端环境变量，不写入网页构建、响应或日志。
- 复用当前腾讯云服务器、Docker Compose 与 `agent.dongjinyue.cn` Nginx HTTPS 入口，不新增公网端口；检查实际代理 IP 头来源，后端端口应只对本机反向代理开放。
- 部署前备份 SQLite / Chroma 数据；数据库迁移向前兼容且不得清空旧管理员会话。更新失败可回滚应用镜像/代码，保留数据卷。
- 以独立提交更新 Agent GitHub 仓库，再按验证结果部署服务器；部署后核验公网访问、会话隔离、额度和容器健康。

## 错误处理与隐私

- 无效管理员凭据返回通用中文错误，不区分邮箱是否存在；Supabase/Auth 不可用时管理员登录安全失败，不降级为管理员。
- CSRF 校验失败、缺少访客 Cookie、身份 Cookie 签名不正确或请求 Origin（来源）异常时拒绝敏感写入。
- IP 摘要密钥缺失时不可静默停用 IP 限流；应用应拒绝启动公开访客模式并记录不含秘密的配置错误。
- 会话所有者迁移失败时不可启动开放访客接口；要么迁移完整，要么以安全关闭模式运行。
- 速率超限返回 429 和 `Retry-After`，用户额度超限返回明确的剩余重置时间，且不把供应商密钥/异常堆栈返回给客户端。

## 验收与测试

- 未登录打开域名进入访客模式；访客不需要共享 token。
- Supabase 登录成功但用户 ID 不等于管理员 ID 时仍按访客处理；伪造用户 ID、角色或无效/过期 token 不提升权限；管理员正确登录可访问既有私有会话并不受访客额度限制。
- 两个访客会话、访客与管理员之间列表/读取/改名/删除/聊天均严格隔离；旧管理员数据迁移后仍归管理员。
- 访客前 10 次 AI 请求获准，第 11 次被拒且模型未调用；失败请求也消耗额度；上海午夜后重置；并发请求不能超过上限。
- 同一 IP 每分钟第 6 次及每日第 31 次 AI 请求拒绝；不同 IP 使用各自 IP 额度；伪造转发头不能绕过限制；管理员免访客 IP 日额度但仍有基础稳定性保护。
- 访客上传、删除文档、删除知识库及不允许的 MCP 操作均拒绝；默认不公开既有知识库，只有显式列入 `PUBLIC_KNOWLEDGE_BASE_IDS` 的知识库可只读检索；原有管理员功能回归测试通过。
- 数据库升级保留 conversations、messages、agent runs、knowledge base 元数据；Cookie 属性、CORS/CSRF、错误脱敏、公开健康检查及窄屏登录/额度布局通过验证。
- 本地完成后运行后端 pytest/compileall、前端 lint/build；服务器部署后检查 HTTPS 主站、API 健康、容器健康及关键隔离场景。

## 不在本阶段实现

- 访客注册、付费额度、设备指纹追踪、CAPTCHA（人机验证）。
- 在个人网站和 Agent 之间共享登录 Cookie；Agent 使用独立登录页，但复用同一个 Supabase 管理员账号。
- 多管理员、多租户知识库、多个后端副本与跨实例分布式限流。
- 将供应商预算告警/账户余额硬封顶能力伪装成已经验证或已经配置的事项。
